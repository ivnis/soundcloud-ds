# Перемотка и оценка обложек

## Перемотка

На нижнем экране **Player** есть сенсорная полоса прогресса и **−5s / +5s**. Крестовина влево/вправо перематывает на пять секунд, вверх/вниз переключает треки. Previous/Next доступны стилусом. Громкость меняют только плечевые L/R.

При нажатии и перетаскивании ползунка показывается целевая позиция и Release to seek. Воспроизведение продолжается во время предпросмотра. Только отпускание стилуса выполняет переход, поэтому движение пальца не запускает десятки HTTP-запросов. Пауза сохраняется после перемотки; выход за начало/конец ограничивается границами трека. Переход точно в конец переводит плеер в Finished, A начинает трек сначала.

Клиент хранит **6 секунд истории и до 8 секунд впереди**: 617400 байт PCM вместо прежних 176400. Переход внутри сохранённого окна выполняется локально, без нового HTTP-потока. Очередь Maxmod сбрасывается, чтобы после перехода не доигрывали старые сэмплы. При переходе за пределы окна запрашивается новый поток и заполняется буфер; задержка зависит от сети и источника.

Для перехода вперёд не более чем на 30 секунд клиент также может использовать уже открытый поток: пропустить входящие PCM-данные до цели с сетевой скоростью и продолжить. Это уменьшает задержку повторных +5s, когда целевая позиция чуть дальше текущего буфера. Далёкие переходы и выход за сохранённую историю используют серверный seek.

Запрос: `GET /v1/audio?track_id=49438146&start_ms=30000`. Заголовок X-Track-Duration-Ms остаётся полной длительностью, X-Audio-Start-Ms сообщает начало возвращённого PCM. Клиент проверяет длину относительно оставшейся части, а отображаемое время учитывает начальную позицию. Отрицательное/некорректное значение даёт 422, позиция не меньше длительности — 416. Интерфейс обрабатывает конец локально, не запрашивая пустой поток.

Сервер держит до 32 недавних разрешённых источников в течение 120 секунд, чтобы seek не требовал каждого раза заново обращаться к SoundCloud API. Ошибка запуска источника удаляет запись. Музыка целиком на сервере не сохраняется.

FFmpeg сначала пробует быстрый input seek. Для HLS, который не отдаёт сэмплы после такого перехода, используется запасной output seek с декодированием/отбрасыванием префикса. Повторяются неудачные загрузки HLS-сегментов. Запасной способ может быть заметно медленнее на длинном треке; ожидание старта seek ограничено 35 секундами, обычного старта — 10. Клиент даёт аудиозапросу до 65 секунд с учётом первоначального lookup. [Различие input/output seek в FFmpeg](https://ffmpeg.org/ffmpeg.html).

## Обложки: исходная оценка ресурсов

Обложки и акцентные цвета уже реализованы; актуальный протокол и настройки описаны в [UI_ARTWORK_SETTINGS.md](UI_ARTWORK_SETTINGS.md). Ниже сохранены расчёты, на основе которых выбран формат.

Для текущего места 64×64 на верхнем экране обложки выглядят вполне посильными. Предлагаемый серверный тракт: получить artwork URL из метаданных SoundCloud, загрузить исходник, обрезать до квадрата, уменьшить до 64×64 и квантовать в 256 цветов. DS получает готовые индексы пикселей и палитру RGB555; JPEG/PNG-декодер на консоли не нужен.

| Формат | Пиксели + палитра при передаче | Развёрнутый RGB555 |
|---|---:|---:|
| 64×64, 256 цветов | 4096 + 512 = **4608 байт / 4,5 КиБ** | **8192 байта / 8 КиБ** |
| 64×64, 16 цветов | 2048 + 32 = 2080 байт | 8192 байта |
| 128×128, 256 цветов | 16384 + 512 = 16896 байт | 32768 байт |

Это размеры выбранного бинарного представления, без небольшого заголовка протокола; степень дальнейшего сжатия зависит от картинки. Вариант 256 цветов предпочтителен для первой версии: заметно меньше полос/ступеней цвета, чем у 16 цветов. Картинка 64×64 уже соответствует текущему месту в интерфейсе.

4,5 КиБ передаются один раз при смене трека и по объёму равны примерно 0,10 секунды текущего PCM. Это не оценка фактической задержки: сетевой RTT и получение исходника могут занять больше. Дополнительные 8 КиБ RAM для текущей обложки невелики; загрузка нескольких будущих обложек потребует ограниченного кеша. Отрисовка добавит копирование 4096 пикселей при обновлении UI, тогда как два полных framebuffer уже содержат 98304 пикселя.

После добавления seek статические секции ARM9 занимают около 1 МиБ, включая аудиоокно и два framebuffer. Это не учитывает runtime heap/стек SDK, поэтому окончательную проверку всё равно надо выполнить на DS Fat, но размер одной обложки не выглядит проблемой.

## Акцентные цвета

На сервере можно выбрать выразительный цвет из той же уменьшенной картинки, отфильтровать почти серые/слишком тёмные варианты и проверить читаемость текста. Цвет передаётся вместе с обложкой. В UI меняются кнопки, заполнение прогресса и индикаторы; основные фон и текст остаются читаемыми. На DS это несколько значений палитры и обычная перерисовка, без обработки изображения.

Загрузка выполняется в фоне с приоритетом аудио и отменяется при смене трека. При отсутствии картинки или ошибке CDN остаются wave-иконка/оранжевый акцент. Сервер кеширует обработанные изображения и проверяет контраст выбранного акцента. Размер готового пакета с 16-байтовым заголовком — 4624 байта.
